# Проверки приложения

Требуется Node.js 24. Внешних npm-зависимостей нет.

```sh
npm test
npm run test:coverage
```

GitHub Actions запускает этот же набор для PR и main. Секреты Supabase и Telegram в CI не нужны. Запросы к API заменены тестовыми моделями.

## Что проверяется

- `app-flows.test.cjs`: 20 сценариев через полный app.js и реальные обработчики событий приложения, минимальная модель DOM и базы.
- `auth-and-data.test.cjs`: 16 сценариев авторизации, нормализации, изменений и экранирования.
- `telegram-handler.test.cjs`: 26 сценариев полного обработчика Edge Function с тестовыми Deno.serve/fetch.
- Семь прежних наборов: конкурирующие сохранения, восстановление, корзина, конфликты, UI, персональные залы, электрические схемы, проверка заполнения.
- `helpers/app-harness.cjs` загружает полный app.js. Экспорт внутренних функций добавляется только в памяти тестового процесса; production-файл не меняется.

Итого Node test runner считает 69 тестов: 62 новых именованных сценария и 7 прежних групп с несколькими assertions. Это не 69 отдельных браузерных E2E-тестов.

## SQL

Запускать через SQL-инструмент в тестовой базе с актуальными миграциями. Все файлы используют BEGIN/ROLLBACK; очередь Telegram не коммитится. Тест персональных залов требует двух подтверждённых администраторов. Не удалять ROLLBACK и не запускать только часть файла.

- `personal-admin-halls.sql`: изоляция пользователей и стабильность залов.
- `telegram-file-notifications.sql`: интеграция триггера с очередью.
- `power-notifications.sql`: электрические схемы и регрессии остальных файлов.
- `telegram-lifecycle.sql`: 14 проверок подписок, дедупликации, остановки, lease, retry и блокировки.
- `backend-contract-audit.sql`: 22 контрактные проверки API и доступа, возвращает массив `name/passed/detail`. **Любая строка passed=false — провал проверки**, а не допустимый пропуск. На 17.11.2026 шесть таких проверок выявляют нерешённые проблемы; см. отчёт.

SQL не запускается в обычном GitHub CI: это требует отдельного тестового проекта Supabase и учётных данных. Последний фактический прогон и ограничения описаны в `docs/test-report-2026-11-17.md`.

## Покрытие

V8 измеряет полный app.js и исходник обработчика Telegram в VM. Отдельные тесты извлечённых функций не привязываются к app.js, поэтому не повышают его процент. Покрытие строк не означает полное покрытие ветвей или пользовательских сценариев. Заглушки сети не проверяют доступность внешних сервисов, SMTP, реальную доставку Telegram или передачу файлов в Storage. Минимальная модель DOM не проверяет CSS, Safari/iOS, фокус, высоту скролла и геометрию страницы.
