# ТЗ на мероприятия

Канбан-доска технических заданий: залы, сцена, звук, свет, видео, документы и персонал.

- Администраторы входят по почте и паролю. Есть регистрация и восстановление пароля.
- Регистрация не выдаёт права: доступ определяется таблицей `admins`.
- Техники открывают конкретное ТЗ без входа. Ссылка отдела задаёт фильтр, а не отдельные права.
- Отметки выполнения общие; введённое имя техника не является проверенной учётной записью.
- Файлы хранятся в публичном бакете `plots`: прямые ссылки доступны без входа.
- Письма отправляет SMTP, настроенный в Supabase; лимиты задаются поставщиком и настройками Auth.

## База данных

`schema.sql` содержит базовые таблицы, RLS и чтение одного ТЗ через `get_event`.
Анонимное чтение списка мероприятий запрещено. Идентификатор в ссылке даёт доступ к ТЗ.

Это пока НЕ полный дамп работающей базы. В действующем проекте дополнительно используются:
`get_checks`, `set_check`, `my_request_status`, `list_admin_requests`,
`decide_admin_request`, а также Storage-политики и настройки Auth.
Перед восстановлением базы нужно экспортировать их из действующего Supabase.
Не запускайте базовую схему как замену всей базы: она не удаляет неизвестные старые политики.

Изменения SQL в GitHub автоматически в Supabase не применяются.
Проверка фактических RLS, RPC и Storage-политик требует доступа к панели проекта.

## Проверки

`node tests/regression.cjs` и `node tests/concurrency.cjs` проверяют конфликты, загрузки, гонки запросов и отметки выполнения. Для статического сайта сборка не требуется.

Порядок установки и ограничения: `DEPLOY.md`. Файлы, сохранённые в ТЗ, физически автоматически не удаляются; серверная очистка требует проверки ссылок. Действующие правила базы выгружаются запросами из `inspect-supabase.sql`.
