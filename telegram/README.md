# Telegram для доски ТЗ

Техник подписывается на одно мероприятие по кнопке в его ТЗ. /stop отключает все подписки этого чата. Когда мероприятие переведено в «Проведено» или помещено в корзину, подписки закрываются. Сообщение о готовности подписано именем из выполненного пункта ТЗ. Оно отправляется только подключённым администраторам. Как и существующая отметка выполнения, имя вводится самим техником и не удостоверяет личность.

## Подключение
1. Откройте [официальный BotFather](https://t.me/BotFather), отправьте /newbot, задайте название и свободное имя с окончанием bot. Токен храните в секретах сервера.
2. В Supabase SQL Editor выполните только [setup.sql](setup.sql). Он создаёт отдельную схему очереди, роль tz_bot_worker и две функции для сайта. Владелец базы задаёт роли уникальный пароль (например через psql и команду \password tz_bot_worker). В строке подключения используйте эту роль. Для Supabase Session pooler сохраните суффикс идентификатора проекта в имени пользователя. Включите TLS.
3. На постоянно работающем сервере соберите контейнер из папки telegram: `docker build -t tz-telegram telegram`. Создайте защищённый файл переменных вне репозитория (права 600). Укажите TELEGRAM_BOT_TOKEN, DATABASE_URL и TELEGRAM_ADMIN_IDS. Последнюю переменную сначала можно оставить пустой. Запуск: `docker run -d --name tz-telegram --restart unless-stopped --env-file /защищённый/путь/bot.env tz-telegram`. Бот использует исходящие соединения. Входящий порт и публичный адрес не нужны. Используйте нового бота без ранее установленного webhook.
4. Вы и ваш коллега открываете бота и отправляете /id. Владелец сверяет номера лично и записывает их через запятую в TELEGRAM_ADMIN_IDS. Пересоздайте контейнер с обновлённым файлом и каждый отправьте /start без параметров. Только эти личные чаты получат сообщения «Зал готов».
5. После установки SQL и запуска бота включите `telegram:true` в объекте TZ_CONFIG в config.js, обновите версию ссылки на config.js в index.html и опубликуйте подготовленные изменения сайта. Без этого кнопки скрыты.
6. В тестовом ТЗ откройте ссылку техника, нажмите «Получать изменения в Telegram», затем «Запустить». Измените время прогонов и сохраните ТЗ. Проверьте сообщение и кнопку «Открыть ТЗ». Отметьте пункт с именем и нажмите «Зал готов». Оба администратора должны получить одно сообщение на этот зал, повторное нажатие не создаёт новую заявку. Проверьте /stop и другое ТЗ без подписки.

## Эксплуатация
Изменения и сообщения о готовности записываются в очередь вместе с действием в базе. Сбой между приёмом сообщения Telegram и подтверждением в базе может привести к повторной доставке. Запускайте одну копию бота. Частота и звук уведомлений зависят от настроек телефона. При необходимости скрыть кнопки отключите telegram в TZ_CONFIG. Для остановки доставки остановите контейнер.
