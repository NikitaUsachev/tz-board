# Запуск @serp_tzbot на Supabase

Сайт остаётся на GitHub Pages. Бот работает в том же проекте Supabase. Команды Telegram принимаются сразу через webhook, исходящие сообщения забирает расписание раз в минуту. При очереди или сбоях возможна дополнительная задержка.

1. Откройте [секреты функций](https://supabase.com/dashboard/project/bhokqekbxbmdjhsqyads/functions/secrets). Создайте TELEGRAM_BOT_TOKEN со значением от BotFather и TELEGRAM_JOB_SECRET — случайная строка из менеджера паролей длиной 40 символов или больше. Не присылайте их в чат. TELEGRAM_ADMIN_IDS пока не нужен.
2. В SQL Editor выполните [setup.sql](setup.sql). Он создаёт таблицы подписок и очередь отдельно от таблиц сайта. Действующие ТЗ сохраняются. Нужны существующие таблицы events, settings, checks.
3. В Edge Functions выберите создание функции через редактор. Назовите её **tz-telegram**, замените содержимое index.ts на [этот файл](../supabase/functions/tz-telegram/index.ts) и опубликуйте. В настройках этой функции отключите проверку JWT (**Verify JWT**). Для входящих запросов код проверяет секрет Telegram, а для задач расписания — отдельный секрет. При использовании CLI эквивалент: `supabase functions deploy tz-telegram --no-verify-jwt --project-ref bhokqekbxbmdjhsqyads`.
4. В Supabase Vault создайте секрет **tz_telegram_job**, вставив туда то же значение, что у TELEGRAM_JOB_SECRET. В SQL Editor выполните [schedule.sql](schedule.sql). Этот скрипт регистрирует webhook и создаёт расписание. Сохраните число setup_request_id. Через несколько секунд проверьте в SQL Editor: `select status_code,content from net._http_response where id=ВАШ_НОМЕР;` — ожидается 200. При 401 проверьте настройку Verify JWT, при 403 — совпадение секретов, при 503 — журнал функции. Повторный запуск скрипта обновляет задание с тем же именем.
5. Вы и Герман в личных чатах с [ботом](https://t.me/serp_tzbot) отправляете /id. Ответ может прийти на следующей минуте. Владелец проверяет номера и в секретах функций создаёт TELEGRAM_ADMIN_IDS со значением в виде двух номеров через запятую. Затем оба отправляют /start. Дождитесь ответа о подключении сообщений по залам.
6. Когда бот отвечает, опубликуйте подготовленную ветку сайта, добавив `telegram:true` в объект TZ_CONFIG в config.js и обновив номер ссылки на config.js в index.html. До включения кнопки скрыты.
7. На тестовом мероприятии подпишитесь кнопкой из ТЗ. Сохраните другое время прогонов и проверьте сообщение и кнопку «Открыть ТЗ». Первый выполненный пункт подпишите именем и нажмите «Зал готов». У обоих администраторов должно появиться сообщение с залом и именем. Повторное нажатие не создаёт ещё одну заявку. /stop отключает подписки личного чата.

Если отправка прервалась между приёмом сообщения Telegram и записью результата в базе, при повторной попытке возможно повторное сообщение. При удалении ТЗ или переводе в «Проведено» его подписки закрываются. Для остановки задачи выполните `select cron.unschedule('tz-telegram-delivery');`.
