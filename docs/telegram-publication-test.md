# Публикация ТЗ в тестовую тему

Администратор открывает сохранённое мероприятие → «ТЗ в Telegram» → предпросмотр → «Отправить в тестовую тему». Повторно открывает окно после правок и подтверждает обновление. Неизменённые сообщения не отправляются. Сохранение не вызывает этот механизм. Существующие личные уведомления подписчикам работают отдельно как раньше.

Адрес жёстко ограничен на сервере: `-1004466460945`, тема `2`. Бот: `@serp_tzbot`. Необходим доступ к группе и право писать в открытой теме.

## Установка

1. Применить `supabase/migrations/20261124132430_telegram_publication_test.sql` (после разрешения на миграцию).
2. Развернуть новую функцию `tz-publish` из одноимённого каталога, включая `content.mjs`, с `verify_jwt=true`. Использует существующие переменные SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, TELEGRAM_BOT_TOKEN. Проверяет пользовательскую сессию через Auth и роль через is_admin.
3. Слить PR и проверить опубликованные app.js/index.html.
4. Администратор отправляет тестовое ТЗ кнопкой, затем меняет одну позицию и проверяет редактирование того же сообщения.

## Проверки

`npm test`: 92 теста, в том числе 13 тестов публикации. SQL-файл `tests/publication.sql` проверен вместе с миграцией в транзакции BEGIN/ROLLBACK на рабочей базе, без постоянных изменений и без отправки сообщений. Браузерный сценарий `tests/browser/publication.cjs` проверяет UI и геометрию Chromium/WebKit с моделируемым API. Это не проверка реальной доставки Telegram.

## Ограничения первой версии

- Файлы представлены ссылками в текстовых сообщениях, не загрузкой документов в Telegram.
- Неизвестный исход sendMessage блокирует дальнейшие отправки мероприятия. Автоповтор намеренно отсутствует. Нужно проверить тему и восстановить связь с фактическим message_id либо подтвердить отсутствие отправки перед сбросом pending через обслуживающий серверный доступ.
- Удалённое вручную сообщение не пересоздаётся автоматически: сервер показывает ошибку.
- Закрытие окна прекращает цикл после текущего запроса. Уже подтверждённые сообщения сохраняются; следующий предпросмотр показывает остаток.
- Отменённые разделы остаются с текстом «Раздел отменён». Это позволяет обойти ограничения удаления старых сообщений и сохранить связь при восстановлении раздела.
- Снимок версии защищает от публикации по устаревшему предпросмотру. При изменениях во время отправки цикл останавливается, уже отправленные части видны и повторно сравниваются при следующем предпросмотре.

## Откат

Вернуть фронтенд на предыдущий коммит; отключить/удалить новую функцию `tz-publish`. Таблицу не удалять: в ней связи с уже отправленными сообщениями. Существующие ТЗ, галочки, файлы, обработчик tz-telegram и рассылочные таблицы миграция не изменяет.
