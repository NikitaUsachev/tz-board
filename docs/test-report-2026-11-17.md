# Отчёт о тестировании ТЗ на мероприятия

Дата: 17 ноября 2026 года. Проверена версия 28.16, исходный коммит `bd9d9e203e7542d968afc5d5b093dd46b99673f0`.

## Результат

Добавлены автоматические проверки приложения, обработчика Telegram и серверных правил. Локальный набор проходит полностью, но серверный аудит обнаружил шесть несоответствий. Поэтому считать всё приложение полностью проверенным и исправным нельзя. Производственный код и схема базы в рамках этой работы не изменялись; обнаруженные дефекты пока не исправлены.

| Проверка | Результат |
|---|---|
| Node.js: приложение и обработчик Telegram | 69 успешно, 0 ошибок, 0 пропусков |
| Контрактный аудит действующей базы | 16 успешно, 6 ошибок из 22 |
| Изоляция персональных списков залов, SQL | Пройдено |
| Уведомления об изменениях файлов, SQL | Пройдено |
| Электрические схемы и остальные типы вложений, SQL | Пройдено |
| Подписки и очередь Telegram, SQL | 14 проверок пройдено |
| Проверка формата изменений git diff --check | Пройдено |

69 — это 62 новых именованных теста и семь существовавших тестовых файлов с несколькими внутренними проверками. Это не 69 браузерных E2E-сценариев.

## Обнаруженные проблемы

Приоритеты ниже — оценка по влиянию на рабочие процессы. Проверки воспроизводятся в `tests/backend-contract-audit.sql`; фактические результаты находятся в `backend-audit-2026-11-17.json`.

| № | Приоритет | Воспроизведение и результат | Предлагаемое исправление |
|---|---|---|---|
| 1 | Высокий | Прямой вызов tg_hall_ready после одной выполненной задачи позволяет объявить зал готовым, хотя другие задачи остались. Интерфейс ограничивает кнопку, сервер не проверяет полноту. | Проверять на сервере все актуальные задачи именно указанного зала, включая дополнительные сцены и дополнительные задачи. |
| 2 | Высокий | get_event возвращает удалённое ТЗ по известному идентификатору. Корзина скрывается только интерфейсом. | Не отдавать удалённые мероприятия через публичный RPC; восстановление оставить администратору. |
| 3 | Средний | set_check принимает отметку для удалённого мероприятия. | Проверять deletedAt до изменения отметок. |
| 4 | Средний | set_check принимает пустое имя техника, хотя интерфейс требует его ввести. | Отклонять пустое или состоящее из пробелов имя на сервере. |
| 5 | Средний | set_check принимает отметку покрытия сцены, у которой покрытие не задано. | Проверять наличие конкретного свойства задачи, а не только ID сцены и допустимый суффикс. |
| 6 | Средний | База принимает два мероприятия с одним залом на одну дату. Проверка занятости в браузере не защищает от одновременного сохранения. | После уточнения идентичности залов между персональными списками обеспечить атомарную серверную проверку конфликтов. |

Это проверки прямого API: они показывают обход ограничений интерфейса, а не обычные нажатия кнопок. Особенно важно исправить первые два пункта.

## Безопасность тестового прогона

SQL-наборы выполнены транзакциями с ROLLBACK. Тестовые изменения и записи очереди не сохранялись; сообщения Telegram не отправлялись. Дополнительная проверка не обнаружила оставшихся мероприятий контрактного аудита. Действующие ТЗ не редактировались.

## Ограничения и дальнейшее покрытие

- Не проверены реальные SMTP-письма, подтверждение входа по почте, передача файлов через Storage и доставка сообщений в Telegram: эти внешние вызовы заменены моделями либо проверена только очередь.
- Не выполнена полноценная браузерная матрица: Safari/iOS, мобильная геометрия, фокус, прокрутка и скачки длинных ТЗ требуют отдельных E2E и визуальных проверок.
- Покрытие ветвей приложения 68,29%; остаются непроверенные комбинации ошибок и пользовательских действий.
- SQL-проверки выполнены отдельно. Обычный CI не запускает их: для регулярного автоматического запуска нужен изолированный Supabase-проект с тестовыми учётными записями.

Добавлена конфигурация GitHub Actions для Node.js 24: проверка синтаксиса и запуск тестов с покрытием при PR и изменении main. Учётные данные внешних сервисов этому набору не нужны.
