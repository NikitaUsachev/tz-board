# Исправления v26

База исходников: GitHub main, коммит 3eb868a5e6e6d868eae14d77eadf067e49469b43.

## Установка кода

Заменить app.js и index.html вместе. Остальные CSS и config.js сохранены без изменений.
Применение schema.sql НЕ является частью обновления сайта. Это базовая схема, а не проверенная миграция действующей базы.
Прежние ссылки на мероприятия продолжают работать. Новые идентификаторы создаются через crypto.randomUUID().
Отдельные токены ссылок и отзыв доступа требуют согласованной миграции Supabase; здесь не добавлены.

## Поведение

- Смена статуса проверяет версию ТЗ; при конфликте обновляет доску и просит повторить действие.
- Список залов сохраняется только если JSON настроек не изменился со времени открытия окна. Остальные поля настроек сохраняются.
- При изменении названия, количества или комментария позиции создаётся новый ID пункта. Прежняя отметка выполнения к новой редакции не применяется.
- Изменение параметров сцены требует повторного подтверждения её пунктов. Простая перестановка оборудования отметки сохраняет.
- Имя техника спрашивается при первой отметке и сохраняется прежним способом. Авторизация для техника не добавлена.
- Параллельные нажатия одной отметки блокируются до ответа; ошибки сети откатывают локальную отметку.
- Устаревшие ответы чтения не заменяют открытое ТЗ; ошибки чтения настроек не маскируются.
- Вложения, уже сохранённые в ТЗ, автоматически физически НЕ удаляются. При удалении ссылки или мероприятия они остаются в хранилище.
  Это защищает копии ТЗ и параллельные сохранения. Для очистки места понадобится серверная проверка ссылок и отдельная очистка.
- Новые несохранённые загрузки очищаются при отмене редактора. Аварийное закрытие браузера может оставить несвязанный файл.
- Удаление зала, используемого в загруженных мероприятиях, заблокировано. Проверку одновременного добавления зала в другое ТЗ нужно перенести в базу.

## Проверки

node --check app.js
node tests/regression.cjs
node tests/concurrency.cjs

Проверки используют исходные функции с моделью базы и сети. Это не проверка живых RLS/RPC и не сквозной тест браузера.

## Что ещё требуется в Supabase

Выполнить inspect-supabase.sql и сверить действующие RPC, RLS и Storage-политики.
Без их определений невозможно безопасно выпускать изменения серверной авторизации, отметок или файлового доступа.
В частности, проверить запрет анонимного чтения списка events, проверки прав в административных RPC,
проверку существования мероприятия и пункта в set_check и права загрузки/удаления файлов.
